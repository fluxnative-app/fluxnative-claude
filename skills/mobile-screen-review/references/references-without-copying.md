# References without copying

A reference raises the bar for craft. It is never a source of content.

## Take

- **Zones:** which blocks the screen has and in what order (summary, list, action).
- **Reading order:** what the eye meets first, second, third.
- **Density:** row height, how many items fit in the first viewport, gaps between groups.
- **Craft moves:** how a figure is set against its unit, how a list ends above a bar, how an
  empty state offers one action.

## Never take

- pixels (no traced layouts, no cropped images);
- palette;
- copy, headlines, labels or sample text;
- brand, logo, illustration style, mascots;
- photos or icons.

## Flag it

These are tier 1 findings.

| ID | Flag when | Fix |
|---|---|---|
| C12 | 3 of the screen's 5 dominant colours are near-identical to the reference's (hard to tell apart side by side) | Re-derive the palette from the product's own brand colour. |
| L14 | 3 or more words in a row copied from the reference; the reference's brand or imagery carried over; a part of the request missing because the reference did not have it | Own words and assets; keep the reference's section order only if the user asked for it; add the missing part. |

Compare the screen beside the reference to check. Name the reference by the label the user
gave it, not by a product name you recognise.

## Screen libraries

If a screen-library MCP is connected, take patterns from it, never pixels.

Use what it returns the same way as any reference: zones, reading order and density. Do not
put its images, copy or product names into the app, the brief or your report.

## In the report

Write which references you used (by the user's label) and, for each, the one or two craft
moves you took from it. If you used none, say "no references".
